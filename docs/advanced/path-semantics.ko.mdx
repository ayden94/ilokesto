# 경로 의미

많은 폼 라이브러리는 점 문자열을 해석합니다. `@ilokesto/form`은 그렇게 하지 않습니다. 이 설계는 API, 스프레드시트, 검색 필터, 분석 시스템에서 `metadata.user.name` 같은 키를 받는 애플리케이션을 보호합니다. 점을 자동 해석하면 문자 그대로의 필드와 중첩 필드가 모호해집니다.

```ts lineNumbers
form.setValue('metadata.user.name', 'literal');
form.setValue(['metadata', 'user', 'name'], 'nested');
```

트레이드오프는 중첩 필드가 조금 길어진다는 점입니다. 대신 예측 가능성이 높아집니다. 재사용 필드 컴포넌트는 `FieldPathInput`을 받고 그대로 전달해야 합니다. 튜플을 점 문자열로 합쳐서 폼 API에 넘기면 필드 의미가 바뀌므로 피하세요.

## 언제 중요해지나

대부분의 애플리케이션은 빠른 시작과 가이드에서 시작하면 충분합니다. 재사용 추상화를 만들거나, 경계 사례를 디버깅하거나, Form이 더 큰 프레임워크 뒤에 숨기지 않고 명시적 경로, 중립적인 스키마 계약, 안정적인 키, 정규화 상태를 선택한 이유를 설명해야 할 때 이 문서를 읽으세요.
