# 필드 경로와 값

`FieldPathInput`은 문자열 또는 튜플 경로를 받습니다. 이 입력은 `getValue`, `setValue`, `getFieldState`, `setErrors`, `clearErrors`, `trigger`, `array`에서 공통으로 쓰입니다. 문자열은 점을 기준으로 나뉘지 않습니다. 중첩 데이터를 가리키는 유일한 방법은 튜플 경로입니다.

```ts lineNumbers
form.setValue('user.email', 'literal key');
form.setValue(['user', 'email'], 'nested value');

const literal = form.getValue('user.email');
const nested = form.getValue(['user', 'email']);
const values = form.getValues();
```

`setValue`는 `SetValueOptions`를 받습니다. `source: 'user'`는 사용자가 변경했다는 의미로 `modified`를 표시하고, 프로그램에서 쓰는 값은 그 신호를 남기지 않을 수 있습니다. `validate: true`는 값을 쓴 직후 검증을 요청합니다. `getValues()`는 정규화된 필드 상태에서 객체를 다시 조립하므로 제출, 저장, 디버깅 전에 호출하기 좋습니다.

## 실무 사용 팁

추상화를 만들 때는 이 레퍼런스를 가까이 두세요. 레퍼런스는 패키지가 무엇을 노출하는지 설명하고, 가이드는 그 조각들을 조합하는 한 가지 방식을 보여줍니다. 어떤 도우미가 `FieldPathInput`, 검증 시점, 배열 재배치를 감춘다면 그 도우미도 같은 정밀도로 문서화하세요. 그래야 나중에 문자열, 튜플, 안정적인 키 중 무엇을 기대하는지 유지보수자가 알 수 있습니다.
