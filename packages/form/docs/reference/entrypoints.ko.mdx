# 진입점

`@ilokesto/form`에는 프레임워크와 분리된 루트 진입점 하나와 네 개의 어댑터 진입점이 있습니다. `CreateForm`, `CreateFormOptions`, `FieldPathInput`, `FieldState`, `FormState`, `FormError`, `StandardSchemaV1`은 루트에서 가져옵니다. 프레임워크 도우미는 `@ilokesto/form/react`, `@ilokesto/form/vue`, `@ilokesto/form/solid`, `@ilokesto/form/svelte`에서 가져옵니다.

```ts lineNumbers
import { CreateForm, type FormError } from '@ilokesto/form';
import { useForm as useReactForm } from '@ilokesto/form/react';
import { useForm as useVueForm } from '@ilokesto/form/vue';
import { useForm as useSolidForm } from '@ilokesto/form/solid';
import { useForm as useSvelteForm } from '@ilokesto/form/svelte';
```

루트 진입점은 프레임워크 피어를 가져오지 않습니다. 어댑터 하위 경로는 패키지의 선택 피어 의존성을 따릅니다. React, Vue, Solid, Svelte 애플리케이션은 각 렌더러를 직접 설치해야 합니다. 가져오기 경로를 명확히 쓰면 Svelte를 React와 같은 훅 구조로 오해해 문서화하는 실수도 줄일 수 있습니다. Svelte는 `register`와 `useFormState`를 제공하며, 같은 모양의 `useField`와 `useRegister`를 노출하지 않습니다.

## 실무 사용 팁

추상화를 만들 때는 이 레퍼런스를 가까이 두세요. 레퍼런스는 패키지가 무엇을 노출하는지 설명하고, 가이드는 그 조각들을 조합하는 한 가지 방식을 보여줍니다. 어떤 도우미가 `FieldPathInput`, 검증 시점, 배열 재배치를 감춘다면 그 도우미도 같은 정밀도로 문서화하세요. 그래야 나중에 문자열, 튜플, 안정적인 키 중 무엇을 기대하는지 유지보수자가 알 수 있습니다.
